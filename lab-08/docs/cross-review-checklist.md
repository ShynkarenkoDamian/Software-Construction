# Чек-лист крос-рев'ю (Завдання 6)

Кожен студент перевіряє частину, яку написав інший, і лишає коментарі в Pull Request.

## Загальне
- [ ] Проєкт збирається й запускається (`logistics.app.Main`)
- [ ] У домені немає `public`-полів
- [ ] У `domain` немає імпортів `java.util.Scanner` і `System.out`

## По патернах
- [ ] **Information Expert:** розрахунки лежать у класі, що має дані (`Cargo`, `Shipment`)
- [ ] **Creator:** `Shipment` створюється лише через `Shipment.create`, невалідний об'єкт створити неможливо
- [ ] **Controller:** `ShipmentController` не містить `Scanner`/`println` і розрахунків
- [ ] **Low Coupling:** CBO сутностей і контролера ≤ 4
- [ ] **High Cohesion:** кожен клас має одну відповідальність, LCOM4 = 1
- [ ] **Pure Fabrication:** технічна робота (формат накладної, ID, парсинг) не в сутностях
- [ ] **Indirection:** застосунок залежить від `ShipmentRepository` і `TrackingNotifier`, а не від реалізацій
- [ ] **Polymorphism:** в коді немає `if/switch` за типом доставки
- [ ] **Protected Variations:** ставки та тарифи сховані за інтерфейсами

## Додатково
- [ ] Закон Деметри: немає ланцюжків `a.getB().getC()`
- [ ] ADR у `docs/adr/` відповідають коду
- [ ] Обидва члени команди можуть пояснити кожен клас
