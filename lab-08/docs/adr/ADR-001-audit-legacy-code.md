# ADR-001: Аудит legacy-коду та вибір стратегії рефакторингу

## Статус
Прийнято (Accepted)

## Контекст
Вихідний код варіанту 8 (логістична компанія) складається з трьох пасивних класів
(`Sender`, `Cargo`, `Shipment`) та одного метода `processShipmentConsole()` у класі
`LegacyLogisticsProcessor`. Код наведено в `docs/legacy/LegacyLogisticsProcessor.txt`.

Виявлені проблеми:

| № | Проблема | Де саме |
|---|----------|---------|
| 1 | Anemic Domain Model: усі поля `public`, у сутностей немає методів | `Sender`, `Cargo`, `Shipment` |
| 2 | Порушення інкапсуляції: об'єкт створюється порожнім і заповнюється ззовні; можна поставити `weightKg = -5` або `status = "abc"` | весь метод |
| 3 | Bloated Controller / Monolithic метод: один метод робить 9 справ (ввід, створення об'єктів, розрахунок ціни, страховка, зміна статусу, текст накладної, реєстр, email, вивід) | `processShipmentConsole()` |
| 4 | Бізнес-логіка поза сутностями (ціна рахується в сервісі, а не у `Cargo`) | блок розрахунку |
| 5 | Спагетті-розгалуження за типом доставки (`if Express ... else if Freight ...`) | розрахунок |
| 6 | Hard-code: ставка 15 грн/кг, 0.5% страховки, номер 770099, id 55, email «logistics@company.ua» | весь метод |
| 7 | Статус — «магічний» рядок (`"Created"`, `"Dispatched"`) | `Shipment.status` |
| 8 | Порушення Закону Деметри: `shipment.cargo.deliveryType`, `shipment.sender.email` | розрахунок, накладна |
| 9 | Висока залежність від чужих даних: метод 31 раз звертається до полів інших класів | весь метод |
| 10 | Консоль, розрахунок, збереження та email змішані в одному місці | весь метод |

## Рішення
Провести рефакторинг у Rich Domain Model із розподілом на шари
`cli -> application -> domain` та `infrastructure`, застосувавши всі 9 патернів GRASP.
Окремі рішення зафіксовані в ADR-002, ADR-003, ADR-004, ADR-005.

## Наслідки
* **Позитивні:** код став тестованим, кожен клас має одну відповідальність, нові типи
  доставки додаються без зміни існуючого коду.
* **Негативні / компроміси:** класів стало більше (≈ 25 замість 4), потрібен «Composition Root»
  (`Main`) для зв'язування об'єктів.
