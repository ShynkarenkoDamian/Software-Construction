# ADR-005: Верифікація якості метриками CBO та LCOM4

## Статус
Прийнято (Accepted)

## Контекст
Потрібно довести, що рефакторинг покращив дизайн (цілі: CBO ≤ 4 для сутностей і контролерів,
LCOM4 = 1).

## Рішення
Метрики рахуємо вручну за методикою з лабораторної: типи `java.*` не враховуємо,
враховуємо лише класи проєкту. Для LCOM4 виключаємо конструктори, статичні фабрики та прості
геттери (дозволено методикою). Детальна таблиця — у `docs/ПОЯСНЕННЯ.md`, розділ «Завдання 5».

Короткий підсумок:
* усі сутності й контролер мають CBO ≤ 4 (Sender 0, Cargo 2, Shipment 4, Controller 3);
* усі класи мають LCOM4 = 1;
* у legacy формальний CBO був 3, але метод 31 раз звертався до чужих полів та мав 9 обов'язків —
  це «прихована» залежність, яку CBO не показує.

## Наслідки
* **Позитивні:** об'єктивні числа для захисту.
* **Негативні / компроміси:** метрики пораховано вручну, не інструментом; для legacy формальні
  числа не відображають реальну проблему, тому додатково наведено кількість чужих полів та обов'язків.
